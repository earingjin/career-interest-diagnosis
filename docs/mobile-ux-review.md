## 자동 저장에서 확인한 결함

`localStorage.getItem`은 성공하지만 용량 초과로 `setItem`만 실패하는 경우, 다음 큐 조회가 오래된 저장소 값을 읽어 메모리의 최신 응답을 덮어쓸 수 있었다. 쓰기 실패 뒤에는 현재 방문 동안 메모리 큐를 사용하도록 수정했다. 응답 변경·다음 문항 위치·전송 완료 후 제거를 함께 확인하는 회귀 테스트를 추가했다.

이 보완은 현재 방문 동안의 응답 보존을 위한 것이다. 기기 저장소 자체가 차단되거나 가득 찬 환경에서는 새로고침 뒤 미전송 응답 보존을 보장할 수 없다. 정상 저장소에서의 저장 실패·새로고침·복구는 브라우저로 별도 검증했다.

## 테스트 데이터 처리

브라우저마다 격리된 새 컨텍스트를 사용했다. 홈페이지 기본 과정은 시작 버튼 이동만 읽기 검증했고, 응답은 무작위 코드의 `모바일UX자동검증` 전용 과정에만 저장했다. 운영 기본 과정 지정을 바꾸지 않았다. 실행 종료의 `finally`에서 테스트 과정만 ID·코드로 지정해 삭제하고 세션·응답·결과가 남지 않았음을 확인했다. 기존 결과 회귀 스크립트와 DB 테스트가 생성한 데이터도 각각 정리했다.

스크린샷에는 테스트 닉네임만 남겼다. 쿠키·토큰·전화번호·DB 키는 보고서에 저장하지 않았다. 화면 증거는 Git에서 제외된 `scratch/mobile-ux/`에 보관한다.

## 확인 한계와 후속 제안

실제 확인한 개선 사항과 다음 제안을 구분한다. 다음 항목은 이번 검증에서 통과했다고 주장하지 않는다.

- 실제 iOS Safari·Android Chrome의 가상 키보드, 주소창·홈 인디케이터, 한글 IME 조합 동작: 기기에서 후속 확인 권장. 이번에는 숫자 키보드 속성과 Enter의 초점 이동을 로컬 Chrome으로 검증했다.
- 글자 확대·스크린리더 전체 흐름은 정식 접근성 인증 범위로 검증하지 않았다. 기존 제목 초점·선택 상태·진행 바와 신규 수정 목록의 기본 키보드 조작 구조를 유지했다.
- 결과 그래프는 작은 SVG 라벨을 사용하지만 같은 점수를 18px 표로 제공한다. 모바일 전용 그래프 라벨 확대는 후속 개선 제안이며, 공유 인쇄 그래프 변경은 하지 않았다.
- PDF 파일 생성·다운로드·A4 인쇄 품질은 별도 검증 단계다. 이번에는 미리보기 진입·가로 넘침·복귀·결과 데이터 불변만 확인했다.
- 서버 콘솔에는 기존 Next.js prerender 도중 fetch 취소 로그가 관찰되었다. 실제 페이지 로드·API·브라우저 흐름은 통과했으며 이번 작업에서 서버 렌더링 구조를 변경하지 않았다.

## 재실행

앱 서버를 켜고 `.env.local`을 준비한다. Playwright가 프로젝트 밖에 설치되어 있으면 `PLAYWRIGHT_MODULE`에 `playwright/index.mjs` 경로를 지정한다. 필요하면 `CHROME_PATH`도 지정한다.

```powershell
$env:MOBILE_BASE_URL='http://localhost:3000'
node --env-file=.env.local scripts/verify-mobile.mjs
```

재실행은 새 테스트 전용 과정을 만들고 종료 시 정리한다. 기본 출력 폴더 `scratch/mobile-ux/after`의 이전 캡처는 덮어쓴다. 다른 경로에 보관하려면 `MOBILE_OUTPUT`을 지정한다.
